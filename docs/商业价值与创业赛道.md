## 二、诚实清单：我们**没有**什么（评委一定会问）

```
✗ 没有商业模式（开源免费）
✗ 没有服务器成本 —— 同时也意味着【没有订阅收入】
✗ 没有账号体系 —— 意味着【没有用户数据可以变现】
✗ 没有硬件 —— 意味着【没有供应链和一次性收入】
✗ 免费竞品很多：Oopz / Discord / 手机投屏 / Snapcast / VoiceMeeter + VBAN
✗ 技术壁垒不高 —— 核心协议、采集、抖动缓冲都是成熟技术，我们做的是整合与验证
```

**★ 但"无服务器、无账号、无数据"这件事要反过来讲**：

```
★ 它不是缺点，是【成本结构优势】：
   · 零边际成本：多一个用户，我们不增加一分钱服务器开销
   · 零合规负担：不碰用户数据，没有隐私合规问题（这在 To B 采购里是加分项）
   · 零部署门槛：不需要注册、不需要联网认证，适合内网/离线环境
★ 也就是说：这个产品的毛利结构天生很好，缺的只是【谁来付钱、为什么付】
```

**这一点必须主动讲出来** —— 评委听到"零边际成本"会重新评估你。

## 三、五条能讲圆的商业化路径（按落地难度排序）

### 路径 1（★首推★）：会议室 / 教室的「多设备音频分发」

**场景**：一个会议室或教室里，一台电脑的声音要送到多个音箱/多个人的耳机；
或者反过来，多个话筒的声音要汇总到一处。

**现有做法的痛**：
- 买专业音频矩阵：几万到几十万，还要施工布线
- 装虚拟声卡方案（VoiceMeeter 类）：每台机器都要装、要配、IT 部门被反复叫去救火
- 蓝牙音箱：一副耳机同时只能连一台设备，而且延迟对不上

**我们给什么**：一个 20 MB 的 exe + 一个 88 KB 的 APK，同一个局域网，零配置、免安装。
**卖什么**：不是卖软件，是卖「**部署与支持**」—— 上门一次配置好、写好使用手册、给一个支持通道。

**为什么这条最可能成立**：需求是真实且高频的，预算在"设备采购/信息化建设"科目下，
不需要说服用户"为一个 App 付费"，而是打包进"会议室改造"里。

### 路径 2：随硬件出货（OEM / 配套工具）

很多音频硬件（无线音箱、音频矩阵、会议一体机、投影）**缺一个好用的配套软件**。
我们的软件可以做成"买我们的硬件，附赠多设备音频分发工具"。

- 收入来自硬件，软件是**差异化卖点**
- 对硬件厂商：省下自研软件的成本与周期
- 这条路的门槛是**渠道**，不是技术

### 路径 3：开源 + 商业支持（Open Core）

社区版免费（就是我们现在的版本），企业版加：批量部署、集中管理、日志上报、
优先支持、定制功能（例如按房间自动分组）。

**这是本项目**最不违背初心**的一条**：个人用户永远免费，赚钱来自企业客户为"省事"付费。

### 路径 4：企业版增值点（在现有产品上加）

```
· MDM 批量分发与预配置（几百台设备一次性推下去）
· 集中管理台（哪个房间的设备在线、在传什么、有没有异常）
· 权限与审计（谁能送给谁）
· 与会议系统集成（腾讯会议 / 钉钉 / Zoom 的音频旁路）
```

### 路径 5：教育采购（学校批量）

学校有大量"多设备音频"场景：语音教室、录播教室、社团活动室。
采购流程长、周期慢，但**一旦进去就黏性很高**。

## 五、壁垒这一节必须诚实（否则一定被问倒）

```
✗ 别说"技术领先" —— 我们的技术是成熟技术的整合，任何有经验的团队两三个月能复刻
✓ 该说三条：
   ① 【场景理解】：我们不是从技术出发，是从"用户的 20 多条真机反馈"出发的
      —— 这一点有完整证据链（一天定位 5 个真机缺陷）
   ② 【部署经验】：免虚拟声卡、免配置这件事，踩过的坑就是资产
   ③ 【开源社区 + OEM 绑定】：一旦随硬件出货，替换成本来自渠道不是代码
```

**评委如果问"大厂抄你怎么办"**，正确的回答是：
> 大厂看不上这个细分 —— 它的天花板不够高，而且要兼容一堆奇怪的设备。
> 我们的优势恰好是"没有服务器、没有账号、能跑在客户自己的内网里"，
> 这三点大厂做不了（他们需要账号和数据）。如果真被抄，说明这个场景被验证了，我们转做服务。

>         所以每一笔收入几乎都是毛利 —— 我们缺的不是成本控制，是把场景做深。

## 七、风险与对策（评委必问）

| 风险 | 对策 |
|---|---|
| 免费竞品多，用户不愿付费 | 不向个人收费；向"不愿意自己折腾"的企业收部署与支持费 |
| 技术壁垒低，容易被抄 | 绑定渠道（OEM）与场景（会议室方案），不靠代码保密 |
| 天花板低（工具类产品） | 承认它是小市场；竞赛里讲"垂直深耕"而不是"平台化" |
| 没有用户数据，无法做增长 | 靠开源社区与硬件渠道获客，不靠数据驱动 |
| 学校/企业采购周期长 | 先从"一个会议室试点免费做"开始，用案例换订单 |
