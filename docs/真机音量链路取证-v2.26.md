## 三、判定

| 可能 | 判据 | 本次结果 |
|---|---|---|
| **A. vol 没到 / 键没命中** | `media_vol` 空、命中键空、诊断"未命中" | **排除**：`media_vol=0.0`、命中键 `9e132394-…`、age 1.1s、三条键都写进了存储 |
| **B. 采集点在音量之前** | vol 变时 `gain` 跟着变、`peak` 不变 | PC 侧自动判定里已有 `vol_verdict=false`（"采集在音量之前（叠加）"）。该结论只有在"峰值≥0.02、vol 变化≥0.15、峰值却持平"时才会写入 → 本进程内确实出现过这样的窗口，**B 有现场证据** |
| **C. 视频 App 走 per-app 音量** | vol 数值不变、听感变了 | `vol` 在 553 秒里恒为 0.0 没有任何变化；`getStreamVolume(STREAM_MUSIC)` 读不到 per-app 滑杆。按你描述的现象（App 音量在动、实际听感/PC 不跟），**C 成立** |

两种不是互斥：B 说明"手机对**媒体流**音量的衰减发生在采集之后"，C 说明"视频 App 那条滑杆根本不写进 `STREAM_MUSIC`"。
两者都只能改手机端的行为 —— 按你定的规则，**本轮不改代码**。

### 需要你拍板的一句话

> 手机的音量要不要改成"按**实际正在响的那个 App**（per-app，Android 15+ 的 app volume / 各家 ROM 的应用音量）采集，而不是 `getStreamVolume(STREAM_MUSIC)`；并且确认采集点是在音量之前还是之后（决定 PC 端还乘不乘 vol）？

你确认后我再动手机端（会出 2.15 / versionCode 29）。现在不动。

## 四、可复现的取证命令（任意时刻可重跑）

### 4.1 取当前生效的网页端口

```powershell
Get-NetTCPConnection -State Listen |
  Where-Object {$_.LocalPort -ge 17800 -and $_.LocalPort -le 17830} |
  Select-Object LocalAddress,LocalPort,OwningProcess
# 以及进程：Get-Process | Where-Object {$_.ProcessName -like 'Audio Mixing*'} | Select Id,ProcessName,StartTime
```

（v2.26 端口被占用时会顺延，所以不要写死 17800；上面这条能直接看出实际在听哪个口。）

### 4.2 一次看全部关键字段

```powershell
$s = Invoke-RestMethod http://127.0.0.1:17800/api/status
$p = $s.peers | Where-Object {$_.online} | Select-Object -First 1
[pscustomobject]@{
  peer        = $p.name;  host = $p.host;  version = $p.version;  send_mode = $p.send_mode
  media_vol   = $p.media_vol;  hit_key = $p.media_vol_key;  age_s = $p.media_vol_age_s
  keys        = ($p.media_vol_keys -join ',')
  vol_verdict = $p.vol_verdict;  volume_note = $p.volume_note
  last_vol    = ($s.peer_volume_debug.last | ConvertTo-Json -Compress)
  gain        = ($s.sinks | Where-Object {$_.route_id -like 'auto-listen*'}).gain
  route_gain  = ($s.sinks | Where-Object {$_.route_id -like 'auto-listen*'}).route_gain
  peak_pre_gain = ($s.receiver.streams | Select-Object -First 1).peak
  mix_peak    = $s.receiver.mix_peak
} | Format-List
```

### 4.3 连续采样（改音量时开着它，看哪一列动）

```powershell
1..20 | ForEach-Object {
  $s = Invoke-RestMethod http://127.0.0.1:17800/api/status
  $p = $s.peers | Where-Object {$_.online} | Select-Object -First 1
  $st = $s.receiver.streams | Select-Object -First 1
  "{0:HH:mm:ss} vol={1} age={2} peak={3} mix={4} gain={5}" -f (Get-Date),$p.media_vol,$p.media_vol_age_s,$st.peak,$s.receiver.mix_peak,

}
```

## 五、这次没证到的部分（如实写）

1. **B/C 的最终区分没做**：需要有人在那台 `.100` 手机上把媒体音量来回调（最大↔一半），
   同时跑 4.3 的采样。三种结果：
   - `vol` 变、`peak` 不变 → B（采集点在音量之前）；
   - `vol` 不变、听感变 → C（per-app 音量）；
   - `vol` 变、`peak` 跟着变 → 采集在音量之后（PC 再乘就是平方衰减，这是第三种要拍板的情况）。
2. **手机当前在采的是系统声音还是麦克风**：PC 的 stats 里没有这个字段（`stream.source` 为空），
   无法从面板确认；只能看手机界面上的音源按钮。
3. **那段"采集在音量之前"的自动判定没有时间戳**：只能证明本进程（20:24 启动）内发生过一次
   "峰值≥0.02 且 vol 变化≥0.15、但峰值持平"的窗口，不能精确到哪一分钟。
4. **对端在 21:22:40 左右掉线**（`online=False`）。复测时请让那台手机屏幕保持亮、App 在前台。
5. 本轮**没有出包、没有改任何代码**（A 不成立；B/C 按你的规则只停在结论）。
