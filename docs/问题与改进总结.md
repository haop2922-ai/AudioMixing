## 一、项目速览

**Audio Mixing（局域网声音投射）**：把同一个局域网里任意设备**正在播放的声音**，送到任意一台或
多台设备上播放。**只走局域网，不经过任何服务器，不注册、不登录、不上传数据。**

- **技术栈**：PC 端 = Python 3.13（纯标准库 + numpy，零第三方运行时依赖）+ 单文件网页控制台；
  手机端 = 原生 Android（Java，零第三方依赖，只用系统 API）。
- **免虚拟声卡**：Windows 用 WASAPI Loopback 采集，手机用 MediaProjection + AudioPlaybackCapture。
- **打包**：PC 端用 **Nuitka onefile** 打成单个 exe（约 20.8 MB；不用 PyInstaller —— 它的单文件启动
  会在 `%TEMP%` 解压自己，被安全软件按动作拦掉，报 `Could not create temporary directory!`）；
  手机端 gradle（JDK 17 + SDK 34 + gradle 8.7）打 debug APK。
- **结构**：`audiomixing/`（PC 引擎 engine.py / webui.py / net/rtpaudio.py / net/discovery.py + `ui/*.html`）
  + `android/`（Proto / Discovery / AudioSend / SendFanout / AudioRecv / LinkPolicy / Engine / MainActivity）
  + `tests/`（PC 单元测试）+ `android/tools/`（手机端离线门禁）。
- **自检门禁**（发版前要过的）：
  - PC：`python -m unittest discover -s tests`（**322 项**）、页面自检（`check_ui_syntax.py` 等）、
    `tools/verify_exe.py --quick`（**12 项**）、`tools/selftest_twonode.py`（**19 项**）、
    `tools/audit_leftovers.py`（**0 错误**）；
  - 手机：7 组离线探针（策略 / 信标 / 一发多 / 抖动 / 收包准入 / 重采样 / 采集源）、
    `python tools/check_apk.py`（**PASS**）、跨语言协议对拍（Java 与 Python 的包 hex 逐字符相同）。

## 三、重要经验教训（都真实发生过）

1. **接收端的"兜底挂载"要分清两种"认不出"**：`_attach_stream_routes` 原来"发送方认不出身份 + 本机
   只有一个播放端就挂到它上"，本意是给"手动填 IP、信标丢了、AP 隔离"兜底，却把**认得出身份、但本机
   没给它开收听**的手机流挂到了别人那条路由上 → **串台**。兜底只给"真认不出身份"的发送方。
2. **引擎里不许依赖界面层的符号**：`engine.py` 里误用只存在于界面层的函数名 `_name_of`，异常被
   `except` 吞掉 → 智连门控**静默失效**。是单元测试当场把它抓出来的。**异常被吞 = 症状变成"功能
   不生效"而不是"报错"**，最难查。
3. **关系图"实线"的判据必须看"这条流真有数据"**：判据若只看"监控页里有没有这条 `route_id`"，而
   "已配置 · 当前没有数据"的行也带 `route_id` → 配了路由但没声音也被画成实线。**判据要盯最底层的
   事实（bytes/rate），不是中间产物（route_id 有没有出现）。**
4. **路由表全网共享 —— 孤儿路由 / 测试残留会留在别人机器的内存表里**：在一台上删，另一台会把它
   **推回来**，必须**两端一起清**；根因用"孤儿路由清扫"堵住（作者+两端都是本机没见过的设备、过宽限
   自动清）。
5. **Nuitka 编译会吃满 CPU，实时音频线程抢不到 CPU 就是一声"咔"**：整个编译进程树降优先级
   （音频优先）；用户听音频时不跑会出声的自检。
6. **防火墙规则与 exe 路径强绑定**：每次换 exe（路径变了）都要**再点一次「放行防火墙」**，否则
   入站规则拦掉点对点音频，表现为"看着在发、对面没声音"。
7. **打包自检必须用临时配置目录 + 临时端口**：否则自检会把随机端口写进用户的真实 `config.json`
   （下次双击面板跑到怪端口，手机和另一台电脑都找不到），或打到用户**正在跑的旧实例**上
   （"面板已响应"是假通过，还会挤掉那个实例）。
8. **只有用户有真机**：凡是"会不会出声 / 好不好看 / 手感如何"，自动化只能到 API / 门禁层，必须写清
   "只有你能验"，并给一个可观察的判据（看哪个数字、哪个开关、哪个颜色）。
9. **跨版本兼容要留后路**：判断"自动路由"不能只看新字段 `auto`（v1.35 才有），要兼容旧版本的
   三特征（`auto` / id 前缀 `auto-listen-` / 标签文本），而且"认出来之后还要**清掉**"，不能只是"不发"。
10. **隐私类改动要收敛成单一状态源**：手机端"停止本机声音却偷偷开麦"的根因是**引擎状态与界面读的
    字段不一致**；修法是界面每次刷新**从引擎现读真实状态**，不再读缓存标志位。

## 四、项目约定与硬约束

- **出货代码/注释/文档/测试里不许出现具体机器名或设备名**（有测试专门盯这件事：出现特定机器名会让
  测试变红）；需要针对某类设备时写"设备类别"或能力判断。
- **UI 文案要精简、写人话**：括号内的注解**不写进按键**（挪到悬停提示）；界面说明用"已停止向 XXX
  发送 —— 它已经 N 秒没有消息了（关机 / 退出程序 / 换了网络）"这类句子，不写术语。
- **设备卡片尺寸要统一**：v1.30 / v1.31 做了三轮才真正做到 —— 根因是 `auto-fit` 会折叠空轨道
  （单张卡被拉满整行）、两栏各写各的宽度且高度由内容决定。做法：`auto-fill` + 两栏合并成**同一条
  栅格** + 统一 `min-height`（局域网卡 240×120、蓝牙方块 160×80；后按用户"同宽就好，不需要同高"
  去掉了强制同高）。用 `min-height` 而非 `height`，好让警告行出现时卡片能长高把话说出来。
- **双维度菜单独立**（像乘法）：页面维度（本机状态 / 设备与路由 / 广播 / 多耳机 / 二维码 / 版本号）
  × 密度维度（简洁 / 详细）；左栏永远恰好一项高亮，两个维度互不影响（v1.30 把"两个菜单塞进同一个
  状态变量"的错改掉）。
- **打包自检不碰用户真实配置**：自检用一次性临时配置目录 + 临时端口，编完就删（v1.31 起）。
- **版本号要与 exe 文件属性一致**：`tools/build_nuitka.py` 的 `--file-version` / `--product-version`
  从 `audiomixing/__init__.py` 的 `__version__` 推（原来写死，改版本号时极易漏掉，导致右键属性里的
  版本和面板上的版本对不上）；面板顶栏也显示版本 + 构建时间。
- **交付规矩**：桌面只留一个能用的成品；同时放 `release\GOGO\`；每个版本备份到
  `版本备份\<版本号>-<时间戳>\`；手机 APK 要同步多处；每次交付核对**所有副本 sha256 一致** +
  **成品时间戳晚于所有源码**。
- **产品铁律**：只做局域网（不做跨网穿透）；手机不准经过电脑（手机之间直连）；每台设备音量单独可调、
  **绝不去动系统音量**；如实告知，界面数字口径必须一致。

## 五、未解决 / 已搁置

1. **智连（自动开关"听 / 送"）语义 —— 已搁置**：经 v1.35（默认关）、v1.40（拦下不给声音）、
   v1.41（两个方向 + 兼容旧对端）三次尝试，仍未达用户预期，**用户已明确搁置**。
2. **手机 → 电脑音质 / 速率的接收缓冲自适应疑点 —— 尚未调**：真机数据里目标缓冲被压到 26ms，
   而迟到 2396 / 溢出 852480 很大，怀疑"把缓冲削到很小"的自适应对抖动偏大的手机链路太激进。
   属音频 DSP，得先有新版手机数据做对照（v1.43 未动）。
3. **蓝牙链路音量在 PC 侧做不到**：Windows 不提供蓝牙链路的音量 / 丢包 / 重传接口，只能在**手机侧**
   调（v1.30 / v1.33 起反复如实说明）。
4. **强杀进程来不及挂断蓝牙连接**：只有正常运行退出（托盘 / Ctrl+C）才主动挂断；任务管理器强杀时
   来不及执行，连接要等系统回收。
5. **防火墙死规则**：每换一次 exe，旧路径规则就变死（指向不存在的文件，拦不到东西但会堆着）。
   清理需要**管理员** PowerShell（会弹 UAC；曾一次 UAC 被取消，所以没清成）。
6. **两端要各自升级才一致**：另一台电脑（2025BJB）长期还是 v1.34，手机端也要装新 APK ——
   都要各自升到 **v2.1**，行为才一致。
7. **网页版手机直连（`p2p.html` / WebRTC）与"手机不准经过电脑"的定位冲突**（它确实借电脑转发信令），
   作为"不想装 App 的手机"备用方案保留，是否撤掉待定。
