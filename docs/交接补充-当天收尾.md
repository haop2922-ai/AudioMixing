## 一、★ 两个新发现的缺陷（未修，建议优先处理）★

### 缺陷 1：面板显示「构建于 未知」

```
现象：GET /api/status 的 build.build_time 是空字符串
      面板顶栏版本行显示：Audio Mixing v1.12 · exe · 构建于 未知
原因：打包时没有把构建时间写进产物（tools/build_nuitka.py 只写了版本号 1.12.0.0）
影响：小（只是版本可见性那一行的观感），但用户会疑惑"为什么是未知"
建议：打包时把时间戳写进一个可读位置（例如 __init__.py 里的常量，或 --nuitka 的常量定义）
```

### 缺陷 2：诊断报告里「程序」一行的判断是错的

```
现象：报告里写「程序 源码运行」，但那一次跑的【明明是 exe】
      ★ 同一份报告上方「版本」行写的是 "exe"，自相矛盾 ★
原因：判断"是 exe 还是源码"的逻辑在打包后失效
      （很可能只看 sys.frozen 或 __compiled__ 的某个形态，没覆盖 Nuitka onefile 的实际形态）
影响：排查问题时会误导 —— 用户会以为自己跑的是源码
建议：判断条件写全（Nuitka 的 __compiled__、sys.frozen、sys._MEIPASS、onefile 解包目录特征），
      并加一条测试钉住它
```

                                        → 点「🩺 诊断」→ 看「程序」那一行（缺陷 2）

## 二、★ GitHub 的坑（已解决）与当前状态 ★

**症状**：
```
fatal: unable to access 'https://github.com/haop2922-ai/AudioMixing.git/':
       Recv failure: Connection was reset
```

**根因**：git 全局配了 `http.proxy=http://127.0.0.1:7890`，
而当时 Clash 的节点**到不了 GitHub**；★ **直连反而是通的** ★。

curl 实测：
```
经代理访问 github.com      → HTTP 000（超时 5 秒）
经代理访问 api.github.com  → HTTP 000（超时 5 秒）
★ 直连 github.com          → HTTP 200（2.16 秒）★
```

**修法**：
```bash
git config --global --unset http.proxy
git config --global --unset https.proxy
git push origin main
```

**结果（2026-10-14）**：
```
To https://github.com/haop2922-ai/AudioMixing.git
   479712d..921feeb  main -> main
★ 线上 main = 本地 HEAD = 921feebd44f71257b8c50ff57370d7a8e49dd0aa
★ 领先 0 个提交 —— 37 个提交全部推上去了 ★
```

**教训**：推送失败先分清是【网络】还是【凭据】：
- `Recv failure: Connection was reset` → **网络**（代理/节点问题）
- `could not read Username for 'https://github.com'` → **凭据**（需要登录一次）
