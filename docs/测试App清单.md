# 真机测试用 App 清单

> 目的：判定一台手机上的**任意 App** 的音量滑杆属于哪一类，并据此决定 AudioMixing 在
> 「外放档 / 静音档」下该怎么乘音量。**真机第三方 App 这一列目前全部未验（需出声条件）**，
> 本文只给出可复现的判据与下载入口，不写任何未经验证的直链。

---

## 0. 先分清两类 App（判据只有一条）

| 类型 | 滑杆实际改的是什么 | AudioMixing 诊断里的现象 | 典型样本 |
|---|---|---|---|
| **A：系统媒体音量** | `AudioManager.setStreamVolume(STREAM_MUSIC, …)` | 拖 App 滑杆 → 电脑诊断 `vol` 序列**跟着变**（`有变化 ✓`） | 哔哩哔哩、抖音、QQ 音乐、腾讯视频 |
| **B：内部增益** | 不动系统音量，只在写 `AudioTrack` 前乘系数 | 拖 App 滑杆 → **声音大小变、`vol` 读数不变** | VLC for Android、YouTube 播放器 |

判定只看 **AudioMixing 电脑端 → 诊断** 里的两处：

1. `vol 序列 <节点>（host）：… [样本 N 个 · 最小 … · 最大 … · 有变化 ✓ / 一直没变 ✗]`
2. `手机采集层：…　档位=外放档/静音档（…）　乘数来源=…`

拖第三方 App 的滑杆时：

- `vol` 变了 → 类型 A。
- `vol` 一直没变，但手机外放/耳机响度确实变了 → 类型 B。
- 两者都没变 → 先确认「送声音」真的在发（诊断里有 `vol` 上报），再怀疑该 App 用的是
  独立音频通道（如 Exclusive / 硬件直通），这类 App 无法被 `AudioPlaybackCapture` 采集。

- **① 系统媒体音量**：直接 `setStreamVolume(STREAM_MUSIC)`，下方实时回读

> 0（回读显示 0）。这正好演示「静音档里系统音量类 App 调不动」；要验①请先切**外放档**。

## 2. 第三方 App 清单

> 下载入口只写「应用宝 / 手机应用商店搜索关键词」或「官方站点」。**不贴 APK 直链**，
> 因为商店链接和版本会变，贴了也容易过期或被替换。

### 2.1 哔哩哔哩（B 站）

- **用来验**：类型 A（滑杆=系统媒体音量）。
- **测什么**：播放任意视频，拖播放器音量条；同时在 AudioMixing 诊断看 `vol 序列`。
- **判据**：`vol` 随滑杆变化（`有变化 ✓`）→ 类型 A。切到静音档后再拖，`vol` 应**不再变化**
  （系统音量被钉死 0）。
- **下载入口**：应用宝搜索「哔哩哔哩」；或手机自带应用商店搜索同名。
- **注意**：B 站有「人声/画面」多音轨与投屏，测试时关掉投屏；HDR/杜比片源可能走独占通路，
  先用普通 1080p 视频测。

### 2.2 抖音

- **用来验**：类型 A（短视频场景，滑杆通常就是系统媒体音量）。
- **测什么**：信息流播放时按音量键或拖 App 内音量条，看 `vol` 是否跟着动。
- **判据**：同 B 站。另需确认抖音是否在后台继续出声（影响「送声音」采集的归属）。
- **下载入口**：应用宝搜索「抖音」；或手机自带应用商店搜索「抖音」。
- **注意**：抖音会申请录音/相机权限，测试时只给必要权限；「直播」场景可能单独走一路音频，
  先测普通短视频。

### 2.3 QQ 音乐

- **用来验**：类型 A（音乐播放器，滑杆通常绑定系统媒体音量）。
- **测什么**：播放标准音质歌曲，拖 App 内音量条；再用耳机验一次。
- **判据**：`vol` 随滑杆变 → A。若 App 内滑杆不动 `vol` 但响度变 → 记为 B（部分音乐 App
  的「App 音量」是内部增益）。
- **下载入口**：应用宝搜索「QQ 音乐」；或手机应用商店搜索同名。
- **注意**：QQ 音乐有「DTS/臻品音质/独占输出」选项，测试前关掉音效与独占，否则可能采集不到。

### 2.4 腾讯视频

- **用来验**：类型 A（长视频，滑杆通常绑定系统媒体音量）。
- **测什么**：播放普通剧集，拖播放器音量条；对比 `vol` 序列。
- **判据**：同 B 站。VIP 杜比/臻彩视界片源可能走独立通路，先测普通清晰度。
- **下载入口**：应用宝搜索「腾讯视频」；或手机应用商店搜索同名。
- **注意**：腾讯视频有「后台播放」，测试时留意是否串到别的采集场景。

### 2.5 VLC for Android（类型 B 的真实样本）

- **用来验**：类型 B（滑杆=内部增益，不改系统音量）。
- **测什么**：用 VLC 播放 `tools\testmedia\` 里的 wav，拖 VLC 内音量滑杆（0–200%）。
- **判据**：`vol` **不变**、但手机输出峰值/响度明显变化 → 类型 B。切到静音档后，
  VLC 的滑杆**仍然有效**（因为它不改系统音量）—— 这是与类型 A 最关键的区别。
- **下载入口**：VLC 官方站点 `videolan.org` 的 Android 下载页；应用宝搜索「VLC」。
- **注意**：VLC 默认可能启用「音频输出=OpenSL ES/AudioTrack」，这两种都能被
  `AudioPlaybackCapture` 采到；若开了硬件直通/独占模式则可能采不到，先恢复默认输出。

### 2.6 汇总

| App | 预期类型 | 关键判据 | 状态 |
|---|---|---|---|
| 自建测试源 | A + B（两个滑杆各验一遍） | ①改 `vol`、②不改 `vol` | **未验（需出声条件）** |
| 哔哩哔哩 | A | 拖滑杆 → `vol` 变 | **未验（需出声条件）** |
| 抖音 | A | 拖滑杆 → `vol` 变 | **未验（需出声条件）** |
| QQ 音乐 | A（可能是 B） | 拖滑杆看 `vol` | **未验（需出声条件）** |
| 腾讯视频 | A | 拖滑杆 → `vol` 变 | **未验（需出声条件）** |
| VLC for Android | B | 滑杆变响度、`vol` 不变 | **未验（需出声条件）** |

## 3. 测试步骤（电脑 + 手机）

1. 手机装 `AudioMixing-手机版-v2.20.apk`（版本号在手机「详情」里确认），电脑装 `v2.32`。
2. 同一局域网，手机「送声音」切**外放档**，开始送声；电脑路由建好、能听到声音。
3. 打开被测 App 播放内容，先记一次**基准**：手机系统媒体音量（比如 8/15），诊断里的 `vol`。
4. 只拖被测 App 的滑杆（不要按系统音量键），观察：
   - `vol 序列` 是否出现新值；
   - `手机采集层` 里的 `合成乘数` 是否跟着变。
5. 切到**静音档**，重复第 3–4 步：
   - 类型 A：`vol` 不再变化（系统音量被钉死 0），拖滑杆无效；
   - 类型 B：`vol` 仍不变，但拖滑杆**声音仍会变**（内部增益不依赖系统音量）。
6. 记录到下表（每台手机、每个 App 一行）。

### 记录表模板

| 日期 | 手机型号/系统 | App/版本 | 档位 | 拖滑杆时 `vol` | 响度是否变 | 结论 |
|---|---|---|---|---|---|---|
| | | | 外放档 | 变 / 不变 | 是 / 否 | A / B |
| | | | 静音档 | 变 / 不变 | 是 / 否 | A / B |

## 4. 两条限制（必须让用户看到）

1. **静音档乘数为 1.0 时，耳机侧相当于满格放。** 从外放档切到静音档可能**明显变响** ——
   外放档里「压到 25%」的那部分信息在静音档不存在。想保留旧音量请把「静音档乘数策略」
   切到「沿用进静音前的音量」。
2. **滑杆本身就是在改 `STREAM_MUSIC` 的 App（B 站、抖音这类），在静音档里调音量无效。**
   系统音量被我们钉死 0，既改不动也读不到；这类 App 要用滑杆请切**外放档**。
   内部增益类 App（VLC、YouTube 播放器）不受影响。

## 5. 一键流程（adb 授权后直接跑）

脚本：`tools\adb_test_flow.ps1`（双击 `tools\adb_test_flow.bat` 也行）。

```powershell
# 只看设备是否授权、抓一轮证据（不装、不设音量、不出声）
powershell -ExecutionPolicy Bypass -File tools\adb_test_flow.ps1 -Action dump

# 装测试源 + 打开界面（不会自动出声）
powershell -ExecutionPolicy Bypass -File tools\adb_test_flow.ps1 -Action all

# 显式设系统媒体音量到 8（不传 -Volume 则完全不动）
powershell -ExecutionPolicy Bypass -File tools\adb_test_flow.ps1 -Volume 8

# 拉手机 SharedPreferences（送声档位、静音档策略等）
powershell -ExecutionPolicy Bypass -File tools\adb_test_flow.ps1 -Action prefs
```

产物默认落在 `tools\adb-logs\<时间戳>\`：`dumpsys_audio.txt`、
`dumpsys_audio_flinger.txt`、`dumpsys_media_session.txt`、`dumpsys_package_*.txt`、
`settings_volume_music_*.txt`、`logcat.txt`、`screen.png`、`phone_prefs\*.xml`。
