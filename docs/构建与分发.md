## 一、结论速查（TL;DR）

```
编译  : 用 Nuitka + zig，必须 -mcpu=baseline（v2.2 事故：AVX-512 会让目标机 0xc000001d）
Python: 用 python.org 官方版，不用微软商店版
产物  : 免解包 onedir（推荐）或单文件；发布前扫 .text，AVX-512(zmm)=0 才允许出包
位置  : 交付物【不要】放在反复编译的目录里，放桌面 / 普通目录 / 安装包
验证  : 让【用户双击】验证，别用自动化工具自己跑一下就当结论
```

```bash
python -m pip install nuitka numpy pyogg opuslib_next qrcode pillow
python tools/build_nuitka.py --onedir --test   # 免解包 + 自检（推荐）
python tools/build_nuitka.py --test            # 单文件 + 自检
```

产物：免解包 zip 约 30.5 MB（解压后 82.5 MB）；单文件约 20.8 MB。

## 二、为什么不推荐 PyInstaller 单文件（实测）

### 症状

```
双击 exe → 弹一个错误框：
    Error
    Could not create temporary directory!
```

### 原因

PyInstaller 的**单文件**模式启动流程是：

```
exe（bootloader + 压缩包）
  → 创建 %TEMP%\_MEIxxxxxx
  → 把内容解压进去
  → 再用里面的 pythonXXX.dll 启动真正的程序
```

**"创建临时目录 + 解压自己"这个动作会被安全软件拦**：

- 火绒的 HIPS / 自定义防护
- 游戏加加（GamePP）的 GAMEPP-IPC-OVERLAY 注入
- 部分企业的终端管控软件

被拦之后 bootloader 直接报上面那个错，程序**根本没有机会运行**。

### 试过但无效的做法（别浪费时间）

```
✗ 换打包参数：--windowed / --console / --onedir / --onefile / --runtime-tmpdir
✗ 换输出目录、换运行目录
✗ 清除文件的"网络标记"（Unblock-File / 属性→解除锁定）
✗ 改配置目录、改程序名
✗ 把 %TEMP% 清理干净、换成别的盘
```

### 有效做法

```bash
# 换打包器：Nuitka 的启动 stub 与 PyInstaller 的 bootloader 完全不同
python -m nuitka --onefile --assume-yes-for-downloads ^
  --enable-plugin=numpy --windows-console-mode=disable ^
  --include-package=audiomixing --include-package-data=pyogg ^
  --include-package-data=opuslib_next --include-package-data=qrcode ^
  --include-data-dir=audiomixing/ui=audiomixing/ui ^
  --output-filename=AudioMixing.exe audiomixing_launcher.py
```

安全软件的"拉黑"往往是**按打包器签名**做的 —— 换打包器等于换了一个身份，
一次即可绕开。这条经验不只对 Nuitka 有效：任何打包器的 stub 都可能被拉黑。

### Nuitka 的额外坑

```
✗ 微软商店版 Python：不提供链接用库文件
     → error: unable to find dynamic system library 'python313'
  解决：装 python.org 官方版（可只给当前用户，不需要管理员，能和商店版共存）

✗ 版本信息参数必须成套给
     → FATAL: Error, company name and file or product version need to be given
  解决：要么都不给，要么 --company-name / --product-name / --file-version / --product-version 全给
```

## 三、目录位置会影响 exe 能不能跑（本次真凶）

同一个 exe（哈希完全相同）放在不同目录，表现完全不同：

```
C:\Users\<用户>\Desktop\app.exe     → 秒开 ✓
E:\app.exe                          → 秒开 ✓
E:\AI\deep blue\app.exe             → 被审查后关闭 ✗
```

**原因**：在一个目录里**反复编译**（几十次构建，每次生成全新 exe），
会不断触发安全软件的规则，最终**该目录**被纳入它**按路径绑定**的拦截范围。
之后这个目录里的**任何**新 exe 都会被拦。

**正确做法**：

```
✓ 编译目录与交付目录分离
✓ 交付物放桌面 / 普通目录 / 安装包，不要放在源码目录里
✓ 一个交付目录里只放【一个】可双击的 exe，避免用户选错
```

## 四、验证纪律（比技术更重要）

本次最大的时间浪费不是技术问题，而是**验证方法错误**：

```
✗ 错：用自动化工具（AI Agent / CI / 脚本）跑一下 exe，看到失败就断定"程序坏了"
✓ 对：让【用户双击】验证 —— 那才是真实结论
```

原因是安全软件会拦**自动化工具自身**的动作。本次日志原文：

```
系统防护,系统加固,DeepSeek Harness.exe 触犯敏感动作防护规则, 已阻止
防护项目：隐藏执行PowerShell
```

→ 自动化工具启动的任何 exe 都会被拦，**与 exe 本身无关**。

**遇到"程序打不开"时的第一步**：

```
① 问清楚：是你双击打不开，还是工具运行打不开？
② 做最小对照：同一个文件【换位置】或【换调用者】各试一次
③ 一次只改一个变量 —— 同时改打包方式 + 目录 + 配置路径 = 永远查不出来
```

## 五、SmartScreen 与未签名程序

```
· 从浏览器下载 / 从 zip 解压的文件带 [ZoneTransfer] ZoneId=3 标记 → 会触发审查
· 即使清掉标记，未签名的【新】exe 仍可能被拦
  （SmartScreen 还看文件信誉：未签名 + 该哈希从没被放行过 = 弹窗）
· 用户点一次「更多信息」→「仍要运行」后，系统按【该文件的哈希】记住决定
  → 同一文件之后永久不弹 ✓
  → 改动一个字节或换个文件名 = 新哈希 → 会再弹一次 ✓
```

**根治办法只有代码签名**（一年几百块）。在此之前：

```
✓ 在说明里告诉用户"第一次运行需要点一次仍要运行"
✓ 用安装包：用户点一次，安装出来的文件不带网络标记，体验更好
```

## 六、CPU 指令集兼容（v2.2 真机事故）

2026-10-21：v2.1 和第一版 v2.2 在另一台电脑上**双击完全没反应**。事件日志是
`0xc000001d`（非法指令），反汇编崩溃偏移得到 `vmovups zmm0, [rdx]` ——
**AVX-512 的 memcpy**。构建机（Ryzen 9800X3D）支持 AVX-512，目标机
（Intel Core Ultra 5 125H）不支持，程序在进入 Python 之前就崩了。

完整复盘见 [`排查实录-AVX512非法指令.md`](排查实录-AVX512非法指令.md)。

### 关键结论

```
✗ 只加 CFLAGS=-mcpu=baseline 不够：zig 的 compiler-rt 在【链接阶段】选实现，
  仍会选 AVX-512 的 memcpy（仍能看到 vmovups zmm0）。
✓ CFLAGS + CXXFLAGS + LDFLAGS 全部 = -mcpu=baseline：
  .text 里 zmm = 0。
✓ nuitka_args 显式 --zig --target-arch=x86_64。
✓ 发布前扫描最终 exe 的 .text（check_portable_isa）；只看编译参数不算数。
```

### 现在的构建门禁

`tools/build_nuitka.py`：

```python
env["CFLAGS"]   = "-mcpu=baseline"
env["CXXFLAGS"] = "-mcpu=baseline"
env["LDFLAGS"]  = "-mcpu=baseline"
```

构建日志必须出现：

```
[build] 可移植性检查: AVX-512(zmm) 指令 0 条 => PASS
```

出现 `FAIL` 时**不要交付**，先查 baseline 参数和编译器。

### 怎么自查一个 exe

```python
# 取 PE 的 .text，逐条反汇编所有 0x62 (EVEX) 候选，统计带 zmm 的指令
# capstone 未安装时，至少检查已知特征字节 62 f1 7c 48（AVX-512 memcpy）
```

### Nuitka 全局缓存权限（2026-10-22）

这台机器上 `%LOCALAPPDATA%\Nuitka\Nuitka\Cache` 被系统/安全软件拒绝写入，
连 `library_dependencies\depends_legacy`、`module-cache\*.json` 都报 WinError 5。
`--disable-cache=all` 管不到 module-cache，纯非沙箱运行也不行。解法已固化在
`build_env()`：

```python
env["NUITKA_CACHE_DIR"] = os.path.join(cache, "nuitka")  # 本次构建临时目录
```

`nuitka_args` 同时加 `--disable-cache=all`。这样不再依赖 `%LOCALAPPDATA%` 的写权限，
也不会把上次的旧缓存喂回来。zig 的缓存仍由 `ZIG_GLOBAL_CACHE_DIR` / `ZIG_LOCAL_CACHE_DIR`
独立管理。

### 另一个教训：没有 launcher.log 的“双击没反应”

先查 Windows 事件查看器 → 应用程序日志里的 `Application Error`：

```
0xc000001d  非法指令（CPU 指令集不匹配 / 产物含新指令）
0xc00000fd  栈溢出
0xc0000409  fail-fast（CFG / 安全软件）
```

比猜“中文路径 / 杀软 / 打包方式”快得多。
