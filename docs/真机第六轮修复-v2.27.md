## 一、Bug-1 手机视频 App 的音量仍不控制耳机

### 改前是什么

Wi-Fi 路径的增益是 **两段相乘**：

1. 手机 `AudioPlaybackCapture` 送出的 PCM **已经带有系统/App 音量**（视频 App 自己的音量、系统媒体音量都会体现在 PCM 幅度上）；
2. 电脑端的 `_volume_factor_for()` 又在本地播放端乘了一次统计包里的 `vol`（`mediaVolumeRatio()` 报的 0..1）。

所以 50% 被乘成 25%（约 −12 dB），25% 变成 6%（约 −24 dB），再往下的中间档几乎听不见，听感就只剩 0% 和 100% 两态。另一个叠加因素是部分 ROM 的 `getStreamMaxVolume()` 只有 1 档，`cur/max` 天生只能报 0 或 1。

### 改后应该是什么

- 手机统计包显式声明 `"vol_in_capture": true`（采集点在音量之后）；
- 电脑端 `_peer_vol_declared` 优先于自动判定，`_volume_factor_for()` 返回 **1.0**，并在状态里写明「手机端已衰减（不叠加）」；
- 手机端 `mediaVolumeRatio()` 改成 `(cur - min) / (max - min)`，并加保护：区间宽度 ≤ 1 时直接报 1.0（不再制造 0/1 假象）；`vol` 只用于诊断，不再被电脑当增益用。

**判据（真机）**

- 改前：手机媒体音量 50% → 耳机明显偏小/几乎听不见；拉到 0% 静音、100% 正常。
- 改后：手机媒体音量 10/25/50/75/100% 应呈连续变化；电脑「只收听」页的该设备应显示 `vol=0.xx` 且增益说明为「手机端已衰减（不叠加）」。

> 说明：这里不再额外读「ROM 的 per-app 音量」API（Android 没有稳定的公开接口）。
> `AudioPlaybackCapture` 本身采到的就是「正在响的 App」的音频，App 自己的音量已经在 PCM 里；
> 手机端只补一个"不重复衰减"的声明，属于用户拍板的「先在手机端处理」。

## 二、Bug-2 关系图

### 2.1 幽灵路由
上一轮已修复，本轮未改。

### 2.2 同一台设备 Wi-Fi + 蓝牙仍分成两个节点

**改前**：`identityMap` 只用 `id / short_id / 名字` 匹配；蓝牙卡片（Windows 侧 `麦克风 (<手机名> A2DP SNK)`）与局域网 peer 对不上时就是两个节点。

**改后**：
- 匹配集合扩展为 `name / observed_bt_name / bt_aliases`，并按 peer 去重计数，避免同一台自报两个同名被算成两台；
- 仍无法自动判定时，**在关系图里拖动两个卡片气泡互相重叠**即可人工合并：拖动时目标卡片高亮、出现「松开即合并为同一台设备」，松手弹警告确认框；合并后的节点卡片上有「拆开」按钮；
- 合并关系存 `config.relation_merges`（蓝牙 ↔ 局域网）或身份注册表（局域网 ↔ 局域网），拆开走 `/api/relation/split`。

**判据**：同一台手机同时开 Wi-Fi + 蓝牙时，图上只应有一个节点；拖动合并后刷新页面/重启程序仍保持；点「拆开」后恢复两个节点。

### 2.3 布局退化（最短路径连接）

**改前**：蓝牙边是「本机 → 蓝牙设备」，与「手机 → 本机」的收听边方向相反，Tarjan 把本机和手机并进同一个 SCC，整张图挤在同一列，看起来像按最短路径乱连。

**改后**：分层只使用**真实送声方向的边**（排除 `kind === 'bt'`），Tarjan 缩点 + 最长路径排层：源在左、目标在右，层级严格按拓扑跳数推进，蓝牙卡片单独列在边上。

**判据**：让 A 手机 → 本机、B 手机 → 本机、本机 → 蓝牙耳机，三个源都应在左列，本机在右列；不应再出现两边同列或大量斜穿。

## 三、Bug-3

### 3.1 取消「收听它」要点两次

**改前**：同端点存在多条语义相同的路由（旧别名 + 当前 id、自动路由 + 手工路由）；删掉一条，另一条继续放声；同时智连还开着，下一包统计（约 2 秒）又把自动路由建回来。

**改后**：
- `set_routes()` 入口统一收敛同语义路由（`_dedupe_routes`，手工优先于自动）；
- 删除一条路由时，语义相同的副本一次性清掉；
- 用户手动删掉**任何**一条收听方向的路由（不再只限自动路由）都会同时关掉那台设备的智连，杜绝 2 秒后重建。

**判据**：点一次「取消收听」，该设备应立刻从收听列表消失，并且 5 秒后不再自己回来；再点一次「收听它」可正常恢复。

### 3.2 广播没开「只听」也能听到 / 开了更嘈杂

**改前**：`routes_for_sender()` 在广播模式下仍会命中残留的具名路由/自动路由，等于绕过「只听」；同一条流被频道路由和具名路由各放一遍 → 叠加、变嘈杂。

**改后**：对端声明广播时，`routes_for_sender()` **只返回频道通配路由**；没有 `config.listen`（没开「只听」）时返回空集合，一个 sink 都不建。

**判据**：广播时电脑没开「只听」→ 完全静音；打开「只听」→ 只播一份，不应比单播更响/更糊。

## 八、真机复验清单（按顺序）

1. 手机装 2.15，确认设置页显示 `2.15`；电脑打开 v2.27，设置页「开机自启动」默认关。
2. Wi-Fi 送声音，手机媒体音量从 100% 慢慢拉到 0%：耳机音量应连续变化，不再只有两态；电脑侧该设备显示「手机端已衰减（不叠加）」。
3. 手机同时开 Wi-Fi + 蓝牙：关系图应只有一个节点；若仍两个，把两个气泡拖到重叠 → 警告框 → 合并；再点「拆开」应恢复。
4. 关系图方向：源设备在左、本机在右，层级按跳数，不应斜穿/同列。
5. 在电脑上点一次「取消收听」，5 秒后不应自己回来；再点一次「收听它」应恢复。
6. 广播时不开「只听」：电脑应完全静音；打开「只听」：只播一份，不应更嘈杂。
7. 打开广播时，所有设备的「智连」应置灰；关广播后恢复原来的勾选。
8. 设置页勾选「开机自启动」→ 注销/重启后服务应在后台就绪；取消勾选后 `HKCU\...\Run` 里的 `AudioMixing` 应消失。

## 九、没做到 / 只有真机能验

- 手机端没有直接读取 ColorOS/HyperOS 的「应用音量」私有 API；本轮依赖「采集 PCM 已含 App 音量」这一事实 + 声明。若真机发现**手机音量完全不再影响耳机**，把 `Diagnosis.java` 的 `"vol_in_capture":true` 改为 `false` 即可回到旧行为（一行，不需改电脑），然后再按"电脑乘一次"路线处理。
- 「同时收听 32 台」在代码里没有独立上限开关，无法用单测证明"第 33 台被拒"；如果真机需要硬上限，要新增一份准入计数。
- 关系图拖拽合并的**真实多设备拓扑**没有浏览器环境可复现（模拟实例只有本机），已用 API 单测 + 静态语法门禁覆盖，真机按第 3 条复验。
- 桌面上的 `Audio Mixing v2.26.exe` 仍在运行（进程占用），无法删除；退出后手动删掉即可，不要误删 v2.27。
