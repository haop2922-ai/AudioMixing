# 修复：广播音源选中了「网络上的另一台设备」+ 采集源空转看不出来

2026-10-12，用户实测「无论哪路都没声音」，电脑端挖出两个设计缺陷。
这份文档记的是**问题是什么、改了什么、改完界面长什么样、怎么测**。

---

## 一、缺陷 1（★核心★）：「广播我的声音」的音源可以选【网络上的另一台设备】

### 现场

用户的真实配置（`%APPDATA%\WaveLink\config.json`）：

```json
"channel_sources":    ["M332BF"],   // 这是他的【手机】的名字，不是本机设备
"broadcast_excluded": ["M332BF"],   // 而这台还被排除了
"broadcast": true
```

`broadcast_excluded` 是手机自己按了「关掉广播」留下的（见 `/api/broadcast` 的设计：
手机退出广播时要记住这个选择，否则自动收编会立刻把它加回来）。两条合在一起：

```
唯一的音源被排除 → 广播永远没有音源 → 一个字节都不发   ✗
界面上没有任何地方告诉他这件事                        ✗
```

用户把「要广播给谁」理解成了「音源是谁」—— **这是设计缺陷，不是用户的错**。
程序的职责是当场说清楚，而不是收下这个设置然后静默失效。

### 改了什么

| 位置 | 改动 |
| --- | --- |
| `audiomixing/webui.py` `set_settings()`（PUT `/api/settings` 的 `channel_sources`） | 每个名字都必须是**本机现在真的能采到的设备**。不是的话返回 400 + 中文原因（`rejected` 字段机器可读），**不再静默存入** |
| `audiomixing/webui.py` `/api/broadcast`（手机那个「广播我的声音」按钮） | 手机没在送声音时不再把它写进音源清单，返回 `warning` 说明要先点「送声音」 |
| `audiomixing/engine.py` `_live_channel_sources()` / 新增 `channel_sources_report()` | 解析不出来的名字不再"静默丢掉"：区分 `remote_node`（是网络节点）/ `phone_offline`（手机没在送）/ `gone`（设备已拔出）/ `excluded`（被排除），每种都有中文原因 |
| `audiomixing/engine.py` `channel_state()` | 把上面那份判定（含"广播会不会真的发出音频"）挂到 `/api/status` 的 `channel` 上 |
| `audiomixing/engine.py` `_local_loop_spec()` | 引擎日志也改说人话（面板和日志同一套口径） |
| `audiomixing/ui/index.html` | ⑥「频道」卡片下多一块红/黄字区域（`#chWarn`），列出用不了的音源 + 一键移除 |

### 改完面板上长什么样

配置里还存着那台手机时，⑥ 卡片里会出现（红框）：

> ⚠ 广播的音源清单里有 1 条现在用不了：「M332BF」是网络上的另一台设备，不是本机的音源 —— 它必须自己打开「广播我的声音」或「送声音」。（它同时还在「已排除」名单里。）
>
> 点下面的「移除用不了的音源」一键清掉，再选本机的采集设备 —— 一般是「扬声器 (...) \[loopback\]」，也就是这台电脑正在播放的声音。网络上的另一台手机/电脑必须自己打开「广播我的声音」或「送声音」。
>
> \[移除用不了的音源（1）\]

音源下拉框（⑥）里**只列本机现在真的能采到的设备**：

```
系统声音 · 扬声器 (Realtek(R) Audio)
麦克风 · 麦克风阵列 (Realtek(R) Audio)
手机（正在送声音） · <手机名>     ← 只有这台手机此刻确实在送声音时才出现
```

网络上的另一台设备**永远不会**出现在这个下拉框里。若硬塞进去，服务端会拒绝并回：

```
这些名字不是这台电脑上的采集设备，不能当「广播我的声音」的音源：
M332BF 是网络上的另一台设备，不是本机的音源 —— 它必须自己打开「广播我的声音」或「送声音」。
```

另外，⑥ 卡片里始终写清"广播实际采的是哪一块"（用户选 A、程序采 B 时，只有写出来才对得上）：

> 广播现在采的是：扬声器 (UU远程虚拟音频设备)（没有音频 ✗）　· 能收到的在线设备 1 台

## 二、缺陷 2：采集源 145 秒没有数据，界面上看不出来

### 现场

采集源是「扬声器 (UU远程虚拟音频设备) [loopback]」（网易 UU 远程的虚拟声卡）：

```
blocks_read: 9512    frames_read: 4565760    alive_for_s: 253.8    last_data_age_s: 145.5
```

采了 95 秒之后设备端就不再有声音进来。`status.sources` 里本来就有
`last_data_age_s`，但面板只写"有数据 · 145.5s 前" —— 看上去一切正常，人却什么都听不到。

### 改了什么

- `audiomixing/engine.py` 新增常量 `NO_DATA_WARN_S = 10.0`，以及对每块采集源的判定
  （`ok` / `stalled` = 超时没数据 / `no_data` = 一块都没收到 / `not_running` = 没在采），
  与设备类型无关（虚拟声卡/蓝牙/USB/有线一视同仁）。
- 面板 ③「本机状态」的音源格子：超过 10 秒没有新数据时标黄并显示 `⚠ 145 秒没有新数据`。
- 面板 ③ 下方新增告警区（`#srcWarn`），显著红/黄框 + 处置建议：

> ⚠ 音源「扬声器 (UU远程虚拟音频设备)」设备存在但当前没有数据：已经 146 秒没有新音频。
>
> 这块设备当前没有声音在播（虚拟声卡空转时就是采不到，比如网易 UU 远程的虚拟声卡）；换成你真正的输出设备试试 —— ⑥的「音源」里改，或 ⑧ 设置 → 采集设备。

### 广播真的没有音源时，直说

广播开着、但实际采的那块设备采不到音频（或那块设备已经不在本机）时，⑥ 卡片里出红框：

> ⚠ 广播没有音源，一个字节都不会发。「扬声器 (UU远程虚拟音频设备)」设备存在但当前没有数据：已经 146 秒没有新音频
>
> 请在⑥的「音源」里选一块本机设备 —— 一般是「扬声器 (...) \[loopback\]」，也就是这台电脑正在播放的声音。网络上的另一台手机/电脑不是本机的音源：它必须自己打开「广播我的声音」或「送声音」。

还有一个相邻的坑也一并说出来（广播开着、但局域网上没人）：

> ⚠ 广播已打开，但局域网上现在没有任何其它设备在线 —— 就算有音源也没有可发的对象（0 台）。

## 三、怎么测（计算机端）

1. 打开控制台（双击 exe 后浏览器会自己开；地址栏是 `http://127.0.0.1:17800`）。
2. 看 ⑥「频道（局域网广播）」这张卡片：
   - 如果里面出现红字「…是网络上的另一台设备，不是本机的音源…」→ 点「移除用不了的音源」。
   - 然后在下拉框里只选**本机**的设备：要广播电脑正在放的声音，选
     `系统声音 · 扬声器 (<你的输出设备>)`；要广播麦克风，选 `麦克风 · …`。
   - 勾上「广播我的声音」。
3. 看 ③「本机状态」的音源格子和下面的告警区：
   - 显示 `⚠ N 秒没有新数据` → 换一块设备（⑥ 的「音源」，或 ⑧ 设置 → 采集设备）。
   - 显示 `有数据 · 0.x s 前` 才算真的在采。
4. ⑥ 卡片最下面那句「广播现在采的是：…（有音频 ✓）· 能收到的在线设备 N 台」——
   这句是最终判据：括号里是"有音频 ✓"、N ≥ 1，广播才是真的在发。
5. 手机端：要么点「听广播」，要么用「收听某台」；只打开网页不点是不会收的。

**离线门禁**（开发用，可复跑）：

```powershell
cd "E:\AI\deep blue\AudioMixing"
python -m unittest discover -s tests     # 全绿
python tools/check_ui_syntax.py          # 页面脚本 + 元素 id + 接口清单
python tools/check_page_js.py            # 需要先起一个源码节点（默认 127.0.0.1:17800）
```

**只有用户能验的**：exe 双击能不能起来、面板上那几行字是不是真的看得懂、
换一块真实输出设备之后 ③ 里是不是变成"有数据"、对端手机是不是真的听到了声音。
自动化工具不能启动 exe（本机安全软件会拦自动化工具启动的程序），
所以这些必须由用户双击验证 —— 见 [`构建与分发.md`](构建与分发.md) 第四节。
