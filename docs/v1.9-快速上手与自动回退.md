## 二、「🚀 快速上手」四步自检（核心）

顶栏最显眼的按钮进入。四步的结论全部由服务端 `/api/guide` 算出 ——
**复用引擎已有的判定**（`capture_state()` / `channel_sources_report()` / peers / 测试音），
面板不自己判断，免得再出现"面板说没问题、引擎其实没在发"。

```
第 1 步：采集源到底有没有声音？
  ✓ 正在采集：耳机 (1MORE HQ51) [loopback] —— 0.0 秒前还有数据
     （电平一直是 0 时补一句：说明声音走的是另一块设备）
  ✗ 采不到声音：「扬声器 (UU远程虚拟音频设备)」设备存在但当前没有数据：已经 145 秒没有新音频。
     虚拟声卡空转时就是采不到 —— 换成一块真有声音的设备。
     [🔧 一键换到有声音的设备] [先验一下候选设备（每块 2 秒）]
     [换成 耳机 (1MORE HQ51)（有数据 ✓）] [换成 扬声器 (Realtek(R) Audio)（未验证）] …

第 2 步：声音发得出去吗？
  ✓ 广播正在发出声音（采的是「耳机 (1MORE HQ51)」），局域网里有 1 台设备能收到
  ✗ 广播没有音源，一个字节都不会发。「M332BF」是网络上的另一台设备，不是本机的音源 …
     [🔧 一键修广播]     ← 清掉用不了的音源、换到真有数据的设备、打开广播，一次做完
  ! 广播正在发出声音，但局域网上现在 0 台设备在线 —— 还没有人听得到。

第 3 步：局域网里能看到别的设备吗？
  ✓ 看到 1 台：M332BF（192.168.0.101）
  ✗ 一台都没看到 —— 两台设备互相看不见时，声音一定发不过去。
     ① 不在同一个 Wi-Fi ② 路由器开了 AP 隔离/客户端隔离 ③ 电脑防火墙拦了入站 UDP
     ④ 手机 App 没开（只打开网页的手机不是节点）⑤ 多个网卡/VPN，发现广播走错网卡
     [🧱 本机防火墙自检（约 5 秒）] [以管理员放行防火墙]

第 4 步：放一段测试音，让人耳确认
  🎧 点按钮 → 本机响 2 秒 440Hz 蜂鸣（从广播实际在采的那块设备发出去），
     手机上点「📻 听广播」，或手机浏览器打开 http://<本机IP>:17800/listen 也能听到（不用装 App）
     [🔔 播放测试音（2 秒）] → [听到了 ✓] [没听到 ✗] → 分别给出下一步指向
```

四步全过时，顶上直接给结论：

```
可以用了 ✓ 手机上点「📻 听广播」，或点「🎧 收听 2024TSJ」。
```

没全过时：

```
还有 2 步没过 —— 按上面的按钮修一下，再点「重新检查」。
```

## 三、采集源空转自动回退（根治第①条）

引擎每两秒检查一次：广播**实际在采**的那块设备是不是"确定采不到声音"。
判据只有一条 —— **真的收到过音频块没有**，与设备类型无关。

```
连续 10 秒没有任何音频  →  找一块别的本机输出设备
                        →  【真的开一次，试采 2 秒】收到了音频块才算"有数据"
                        →  换过去，写进配置，并在面板上明确告知
```

面板上的告知原话（黄框，在 ③ 本机状态）：

```
🔁 已自动把音源从「扬声器 (UU远程虚拟音频设备)」换成「耳机 (1MORE HQ51)」——
   「扬声器 (UU远程虚拟音频设备)」设备存在但当前没有数据：已经 11 秒没有新音频
   本次切换发生在 14 秒前，已经写进配置（下次启动不会再走那块设备）。
   如果这不是你想要的，在 ⑥ 的「音源」里改回来。
```

必须守住的几条（都有回归测试）：

- **只在确实有替代设备、而且试采真的收到音频时才切**；没有替代就只告警，绝不瞎切。
- 用户手动指定过设备时**切换要留明显记录**：日志一行 + 面板黄框 + 写进 config.json。
- 切换后立刻持久化（`channel_sources` 与 `source_device` 一起改），下次启动不再走坏设备。
- 冷却 180 秒，不会在几块设备之间来回跳。
- 坏设备被看门狗每 6 秒重建一次（`alive_for_s` 会被清零），所以"一直没数据"的计时
  **跨重建累计** —— 否则永远等不到那 10 秒，自动回退永远不会触发（这是实现时踩到的坑）。

## 五、④ 电脑端路由改成「对设备的按键」（照手机端）

用户原话：

> 手机的 UI 确实相对而言更美观，电脑端的路由可以效仿，**也不要拖动了，都改成对设备的按键**。

以前 ② 是"把设备拖进「要听谁的」/「用谁的耳机听」两个框"生成路由 ——
要用鼠标拖，还得先理解"源 → 目标"这套模型。现在改成**以设备为中心**：

```
② 设备与路由                     每台设备一张卡片，点按钮就连上

  局域网里的设备
  ┌──────────────────────────────────────────────┐
  │ 2024TSJ  [本机] [可当音响]                     │
  │ 192.168.0.106                                │
  │ ▓▓▓▓▓▓▓▓▓▓▓░░░░░░░░░                        │
  │ 播放电平 62.0%                                │
  │ 这台电脑：用下面的 ⑥ 频道开关决定它广播什么、听什么 │
  └──────────────────────────────────────────────┘
  ┌──────────────────────────────────────────────┐
  │ M332BF                                       │
  │ 192.168.0.101                                │
  │ ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓                        │
  │ 上行 1536 kbps                                │
  │ [✓ 正在收听它的（点一下断开）] [🎤 送给它] [测连通] │
  └──────────────────────────────────────────────┘

  已经连上的（谁的声音 → 放到谁的耳机）
  M332BF → 本机   音量 [====] 1.00   pcm_s16   [静音] [断开]

  ▸ 高级：一次连多台 / 指定输出设备 / 音量 / 编码
```

- 卡片上两个按钮就是一个方向的路由：`🎧 收听它的`（它的声音放到本机耳机）、
  `🎤 送给它`（本机的声音放到它的音箱）；**再点一次就断开**（按钮会变成 `✓ 正在…`）。
- 卡片内容照手机端那套：名字 · 平台/IP · 状态标签（本机/可采声音/可当音响/离线）·
  电平条（本机看播放电平，对端看上行码率或下行缓冲）· 按钮。
- **能力一个没丢**：多目标混音、每路音量、静音、编码、指定输出设备
  都收进「▸ 高级」里，改成**勾选 + 按钮**（不再拖拽）。
- 路由表每行仍是：谁 → 谁、音量滑杆、编码、`静音`/`断开` 按钮。
- 「常用例子」的说明也改成了按钮式的说法。

   换回来之后告诉我们，我们再看要不要给个"别自动改"的开关。
