## 3. 项目里没有、必须你自己在 TRAE 界面里截的（提交前必补）

### 3.1 AI 对话（至少 2 张，建议 3 张）

项目里没有任何一张 TRAE 对话截图，这是最缺的一类。**不要截只有结论的一句「已修复」**，
要能看出「提问 → 排查 → 证据 → 改动」的往返。建议选下面这一条，信息最完整：

**首选：音量到底断在哪一环**

搜索关键词：`平方`、`raw_peak`、`4096`、`vol_q14`、`553`。

要包含的三段：

1. 你的提问：手机音量调小一半、电脑那头只剩四分之一，像平方；已经排除了哪些可能。
2. TRAE 的排查过程：两轮假设（PC 键匹配 / 采集时机），以及把「上报值、命中键、收到峰值、
   混音峰值、播放系数」一起打出来的那一步；最好带到 `553 秒、约 106 MB 的 PCM 全零`
   和 `raw_peak 一直是 0.3662` 这两个证据。
3. 最后的改动：电脑端系数恒为 1.0、手机端把音量绑到送声档位；以及新增的门禁
   （电脑侧链路检查、手机侧 21 条断言）。

**备选（任选一条，各 1 张即可）：**

- 广播被误判成点对点：关键词 `want_listen`、`broadcast`、`未接受的点对点`。
  要包含「为什么不再猜发送端意图、改成只认显式声明」的那段判断。
- onefile 自启动写错路径：关键词 `onefile`、`sys.frozen`、`注册表`、`NUITKA_ONEFILE_PARENT`。
  要包含临时解包目录导致路径失效的现象和最终过滤逻辑。
- 测试污染用户配置：关键词 `AUDIOMIXING_HOME`、`config.json`、`沙箱`。
  要包含「启动真实 exe 改写了用户配置」这个事故和沙箱改造。

截图要求：保留 TRAE 的会话标题、模型名、工具调用卡片；分辨率至少 1280 宽；
一张图里如果字太小，宁可拆成两张，也不要缩到看不清。

## 4. 建议的提交顺序（合计 7～8 张）

1. `01-运行效果-主界面-v2.32.png` —— 先让评委看到成品。
2. AI 对话 1：我提出的问题（音量平方衰减）。
3. AI 对话 2：TRAE 的排查过程与关键数字。
4. `02-运行效果-设备关系图.png` —— 核心界面之一。
5. 代码 diff：`_peer_send_mode_for` 或 `totalQ14`。
6. `03-运行效果-广播送声-v2.32.png` + `04-运行效果-设置与静音档策略-v2.32.png` —— 功能落点。
7. 终端门禁：单测 / verify_exe / 构建自检。
8. 版本备份目录或多份哈希一致。

这样评委能顺着「我提问题 → TRAE 排查 → 改代码 → 跑门禁 → 出成品」看完整条线，
而不是只看到几张好看的界面图。
