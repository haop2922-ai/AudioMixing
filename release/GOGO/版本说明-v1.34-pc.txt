━━━ 1. 手机版左上角角标（你说的第 1 条）━━━

  根因是我上一轮漏了半边：只换了**桌面上的启动图标**（mipmap 里的 ic_launcher）和电脑端/网页上的
  方块，**手机 App 界面里那枚角标一个字节都没动** —— 它画的还是更名前的旧标识「四条音频柱」。
  所以你在手机上看到的就是"外面的图标换了、里面的角标没换"，里外又对不上。

  现在那枚角标画的是和 exe 图标 / APK 图标 / 电脑面板 / 监控窗**完全同一套**：
  140° 蓝色渐变圆角方块 + 白色 A。
  （A 的竖直位置是用 `FontMetrics` 算出来的，不是把基线放一半 —— 那样字会明显偏上。）

  ★ 这一条**必须重装 APK** 才能看到；这台电脑上跑不了安卓界面，所以它只做了静态校验 + 编译通过，
    真机效果要你装上确认。

━━━ 2. 蓝牙每次操作整个模块都重刷（你说的第 2 条）━━━

  根因：`btToggle` 一上来就把**整个蓝牙列表**的 innerHTML 换成「正在断开…」—— 那一秒里
  **所有**蓝牙卡片全部消失，回来再整块重建，滚动位置也跟着跳；「自启」同样是整块 loadBluetooth()。

  现在按**卡片**定位：每张卡片有自己的 DOM 节点（`btcard-0/1/2…`），操作时只给那一张加忙态
  （在它内部写一句灰字 + 暂时禁用它的按钮），回来**只替换那一张**。

  实测（真开页面 + 在别的两张卡片上打探针属性）：被点的那张确实被换掉了，另外两张在整个过程中
  **连 DOM 节点都没被换过**（跨过一次 2.5 秒的自动刷新仍是同一个节点）→ "只有被操作的那张动"成立。

  隐藏 / 恢复隐藏仍然是整块重画 —— 那种情况"列表里到底有哪几张卡"真的变了，重画才是对的。

━━━ 3. 二维码 / 版本号的二级菜单（你说的第 3 条）━━━

  一级菜单停在「二维码 / 版本号」这两页时，二级菜单那四个标签（本机状态 / 设备与路由 / 广播 /
  多耳机）整排不显示 —— 那两页不属于任何一个二级标签，摆着只会让人以为点了会有反应。
  右边那一排工具按钮（放行防火墙 / 诊断 / 快速上手 / 测试音箱 / 刷新）**留着**：它们不是二级菜单。

  ★ 顺带修掉一个连带缺陷：这两页本来就没有"密度"这一维（代码注释里一直是这么写的），但
    「版本与运行」这张卡片带着 `full` 类，会被简洁档的 CSS 整张藏掉 ——
    **简洁档点「版本号」原来看到的是一整页空白**（新加的「设备关系图」也会跟着消失）。
    现在这两张卡片在简洁档照常显示，而「日志」仍然只在详细档露 —— 没有用 !important 一把盖住整页。

━━━ 4. 设备关系图（ComfyUI 风格，你说的第 4 条）━━━

  放在「版本号」那一页（「版本与运行」下面）。按你当场选的两条做的：

  · **可操作：拖线 = 真建路由** —— 从一台**右边的圆点**拖到另一台**左边的圆点**，
    就真的建一条「它送给你」路由（方向就是拖的方向），和点设备卡片上的按钮等价；
  · **连设备之间的路由也画** —— 不只是本机↔设备，两台设备之间已有的路由也画。

  图长这样：
  · 节点：本机（蓝色高亮）、局域网设备、蓝牙设备（没连上的淡一格、只画不连）。
    节点可以拖着摆位置，摆过的位置会记住（存在浏览器里），右上角有「重排」放回自动排列。
  · 线：柔和的贝塞尔曲线，按连接方式分色 —— **Wi-Fi / 点对点 = 蓝**、**蓝牙 = 绿**、
    **广播 / 收听 = 橙**；实线 = 现在真的有连接，虚线 = 连上了但当前没有声音在流。
  · 点一条线 = 删掉那条路由（会先弹一次确认）。广播/收听那两条橙线没有路由可删，
    它会指你去「广播」那一页关开关。蓝牙节点故意**不给圆点**：蓝牙是点对点的物理链路、
    不是路由端点，拖不出路由 —— 硬拖会给一句人话，而不是静默什么都不发生。

  技术上守住的几条（都是这台机器的硬约束）：
  · **不引任何外部库** —— 纯 SVG + 手写 JS；局域网里外链根本加载不出来，自检脚本也会判不合格；
  · 线"真的在通"取自 `/api/monitor`；
  · **蓝牙那一份复用蓝牙卡片自己读回来的数据，关系图一次枚举都不发起** ——
    冷缓存的蓝牙枚举要起一个约 3 秒的 PowerShell，而且**枚举本身会扰动正在保持的蓝牙连接**
    （`bluetooth.py` 里那条"绝不能在面板轮询的请求上跑"的禁令就是为它写的；我第一版图里
    每 2.5 秒问一次 `/api/bluetooth`，自查时发现正好踩在这条禁令上，改掉了）。

  实测（真开页面、真拖、真点）：
  · 拖出来的线**在服务端真的建成了一条路由**（不是只弹个提示 —— 路由表里查到了那条新路由）；
  · 点一条线确实把对应路由**从路由表里删掉了**（服务端状态核对过）；
  · 三种颜色的线、实线/虚线、以及**设备↔设备**那条线都画出来了（用三台节点实测）。
