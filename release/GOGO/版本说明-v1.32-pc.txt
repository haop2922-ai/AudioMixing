━━━ 第 1 件（最要紧）：拖音量时应用**整个消失** —— 真崩溃，已复现并修掉 ━━━

  Windows 事件日志里的硬证据：2026-10-16 23:26:50
      出错应用程序  Audio Mixing v1.31.exe
      出错模块      audiomixing_launcher.dll
      异常代码      0xC00000FD        ← **栈溢出**
  时间正好落在你说的"拖音量时电脑端应用重启"那几分钟。

  我没有停在猜：写了个探针（模拟手机每 2 秒发一条统计/控制包），一次就复现，栈里是同一段循环：
      set_routes() → apply_routes() → _handle_peer_requests()
        → _apply_shared_gain() / _grant_listen_request() → set_routes() → apply_routes() → …
  实测嵌套到 **198 层**。为什么：`set_routes` 结尾要 reconcile，而 reconcile 又会处理手机刚发来的
  控制消息（它请求收听我、或同步音量），处理时又回头改路由表 —— 手机每 2 秒一条就一层层往下套。
  源码运行时 Python 只是慢（**每条控制消息白跑几百遍完整 reconcile，这就是"反应很久"的根因**），
  Nuitka 打包版每帧占的 C 栈更大，1MB 线程栈当场撑爆 → 应用直接没了。

  修法：apply_routes 加**同线程重入保护**（内层直接返回；外层那一轮带着新的路由表把收发两端
  reconcile 完，一件事都不漏）。崩溃消除，顺带把"卡/慢"一起去掉。
  回归测试 2 条：不许再递归（**并且必须真的触发过重入，否则算假通过**）、路由与共享增益一个都不许丢。

━━━ 第 2 件：两边音量同步慢 / 跨端自动启停慢 ━━━

  根因：唯一携带「我在送你声音 / 请自动收听我 / 这条路由的音量」的消息是 `_send_peer_stats`，
  而它是 **2 秒一次**的节流循环 —— 拖完滑块对端最多等 2 秒（再叠上对端自己 2 秒一轮）。
  现在：电脑端本机一改就**立刻**补发（叫醒维护循环去发，面板请求不为一个 UDP 包等网络）；
        手机端统计发送循环改成可被叫醒，拖滑杆立刻发包（**这就是要装 v3.3 的原因**）。
  效果：两端音量、以及"电脑开始送音→手机自动开收音 / 电脑停送→自动关"，从"最多 2-3 秒"变成几十毫秒。

━━━ 第 3 件：图1 中文乱码（"就是中文出现了点问题"）━━━

  根因不是字体，是**编码**：网络自检那段 PowerShell 输出在中文 Windows 上是 **GBK**，
  面板却按 UTF-8 解、解不出来就整片替换成方块 —— 于是
      Audio Mixing - LAN audio casting → E:\AI\Audio\AudioMixing\??\v1.12-…\??\audiomixing v1.12.exe
  只有中文目录名（版本备份/成品）和网络位置名变成 "??"，英文照旧正常。
  现在先按**字节**读回来，再依次试 UTF-8 / 系统 ANSI —— 两种机器都对，并加了回归测试。
  （顺带清掉了自检留在你配置目录里的 last-run.txt，它里面还写着 57590 那个测试端口。）

━━━ 第 5 件：广播 —— 按你钉死的口径重做（和路由**完全独立**，像局域网里的 FM 电台）━━━

  你的原话：「广播是和路由独立开的。你别混一起了。广播就是设备想说就说想听就听，
  但是不能关闭或者开启其他设备的听说。也不能对特定设备关闭听。就像 FM 广播一样。」

  ①「电脑开只听没有声音」—— 真根因找到并修了：`desired_sinks()` 原来对**所有**规则都要求
     "至少有一个在线对端"，可频道收听那条的来源是通配 `*`，收听方本来不需要先认识广播方。
     于是对方还没被登记成在线设备时（手动填的 IP、信标丢了、路由器做了 AP 隔离），播放端一个都不建：
     开关亮着、一个字节都没有、面板上看不出为什么（探针复现：把对方标离线后 sinks 变空，
     包到了只能写 "has no local sink yet"）。现在通配规则不再要求"先认识对方"，
     认不出身份的流也落进频道那条 —— 谁在发就听谁。
  ②「手机一开广播，所有设备卡片上的『送声音』全被点亮」—— 已按 FM 口径改掉：
     · 手机端 `isSending()` 不再把"广播开着"算进去 —— **卡片只反映你自己勾过的选择**，
       广播不点亮任何一张卡；"我正在广播"只由上面那个 📢 开关/状态显示。
     · 手机端**不再**对广播覆盖的目标报 want_listen（那是"我在针对性送给你、请你自动打开收听"，
       等于替别人去开它的收听路由）。广播这条线只发声音，**要不要听由对端自己那台决定**
       （对端自己开「听广播」/「只听」）—— 和你说的"不能被别的设备开关听说"一致。
     · 你上一轮选的"广播期间禁用逐台『送声音』"我**撤回**了 —— 按你最新的口径，
       广播和路由是两条独立的线，逐台按钮照常可用（广播开着也能单独补送给某台）。
     · 手机上那条「送」音量条在广播时仍然显示真实电平（不然会显示 0 骗人），
       但按钮的亮/暗仍然只表达你自己的勾选 —— 这两件事分开了。
     · 电脑端同理：广播那条频道会话不再报 want_listen；「送给它」按钮不因广播变灰。
  ③ 顺带修掉一个会"音量翻倍"的坑：我既开着「听广播」又点名收同一台时，两条规则都会命中它，
     同一声声音会被两个播放端各放一遍。现在**具名路由优先**，认不出身份才落频道那条
     （手机端那句"只会播一路、不叠加"在电脑端也成立了）。
