★ 这是**统一版本号**的发布版：PC 端和手机端这次都输出 **v2.1** —— 诊断报告 / 设备卡片上
  看到的版本号一致，用户能一眼确认"手上装的是同一批货"。

先说操作上的事：

  ① 桌面 exe 换成 `Audio Mixing v2.1.exe`，**路径又变了** → 要**再点一次「放行防火墙」**
     （托盘右键，或面板右上角那颗按钮）。不点的话点对点发音频会被入站规则拦掉。
  ② 桌面**只留最新一版**（旧的 `Audio Mixing v1.42.exe` 本期清走，桌面只留 v2.1 一颗）。
  ③ 手机端**要装新 APK**：`AudioMixing-手机版.apk`（versionCode 15 / versionName 2.1）。
     面板「扫码装 App」优先取 **exe 旁边那份** APK —— 所以桌面上这两份要放在一起（现在就是一起的），
     扫码拿到的才是 v2.1。

━━━ 本版相对上一版（PC v1.44 / 手机 v3.7）新增（就两条）━━━

  ① 手机端：**断联超过 2 分钟的陈旧设备卡 / 提示会被清掉**
     用户原话：「这种已经信号断联两分钟的就直接删掉就好了。不然全堆积在程序里」。

     根因（两层）：
       · 安卓 `Discovery.peers()` 返回**全部条目**，没有"新鲜度"过滤；
       · 而过期清扫 `sweep()` 挂在 `rxLoop()` 里，可 `rxLoop` 在发现 socket 为 null 时会**整段
         `continue`** —— 于是"这一下没网"的期间，过期清理被**跳过**，早就断联两分多钟的对端
         一直留在列表里（用户真机截图：一张 2025BJB 的卡片写着"还没收到它的心跳"，上面还有一行
         "已停止向 192.168.0.103 发送 —— 它已经 128 秒没有任何消息了"）。

     修法：
       · `LinkPolicy` 新增 `CARD_STALE_MS = 120000` 与纯函数 `cardStale(ageMs)`
         （"从没见过"= NEVER 不算陈旧，那是"还没出现"，不是"走了"）；
       · `Engine.peers()` 按它过滤列表（超出 2 分钟的直接不返回，卡片就没了）；
       · `Engine.collectSendTargets()` 把**断联超 2 分钟的陈旧送声目标**连同它们的意图一起清掉，
         那行"已停止向 XXX 发送"的陈旧提示也随之消失；
       · 修好 `rxLoop()` 里被 `continue` 跳过的 `sweep()` —— 没有 socket 时也要走到过期清理，
         睡一下再取新的 socket，线程不退出。

  ② 手机端**自报的版本号原来是写死的 `1.0.0`**（PC 这边设备卡片 / 对端列表上显示不准）
     → 改成读 `BuildConfig.VERSION_NAME`（`Discovery.APP_VERSION = BuildConfig.VERSION_NAME`）；
       同时在 `app/build.gradle` 里打开 `buildConfig true`（AGP 8 默认不生成它），
       并把 `versionCode` 升到 15、`versionName` 改成 `2.1`。

━━━ 累积内容：v1.35 → v1.44 的修复清单（每条一行：问题 → 修法要点）━━━

  · v1.35 电脑主动送声音、手机不自动接收 → 拆掉两层根因（① "关过一次就永不再自动"的黑名单
    `listen_optout` 过期条件别扭、对方一直请求就永久卡死；② 删除记忆 `_dropped_ids` 挡住了固定
    id `auto-listen-<短id>` 的自动收听路由复活）：判据只剩「智连」开关一条；建自动收听路由前先清掉
    自己的那笔删除记忆。手机端同一病根用 `LinkPolicy.listenAction` 拆掉。
  · v1.35 关系图只允许从"本机"侧拖线 → 只有本机卡片有拖拽起点（左右两个方向），局域网/蓝牙卡片
    只给落点；落点判定从 `elementFromPoint`（会被线抢命中）改成按卡片矩形的几何判定 `relHitNode`；
    同一条线拖第二次直接提示"这条线已经有了"（原来会堆两条重叠路由）。
  · v1.35 关系图不滚、Ctrl+滚轮缩放 → 图 `overflow:hidden`（一条滚动条都没有），靠"按住空白拖"
    逛图；Ctrl+滚轮只缩图（围绕指针），不按 Ctrl 的滚轮照旧交给页面。
  · v1.35 回环警告 → 只在**点对点**上判闭环：每一页最上方出现红色警告条 + 那几条线标红加粗，
    照常运行、"后果自负"（广播+只听天然两条反向线，不当回环报）。
  · v1.35 点对点"已配置 · 当前没有数据"那两行缺「断开」 → 补齐，并把语义统一成一个：
    监控页上点对点行的「断开」＝**删掉这条路由**（和设备卡片完全同一个意思）。
  · v1.35 每台设备卡片第 4 键「智连」（默认关） → 开了就自动接受与这台设备的"听 / 送"；
    手机端**只自动开"听"、不自动开"送"**（不让人悄悄拿走麦克风）。同时整块删掉旧的全局自动收听
    开关 + 黑名单接口（`/api/listen/optout`）与那些"随机弹提示"。
  · v1.36 测试残留路由（图1 一堆 `preview-…` 行） → 是同一台电脑上起的三台临时预览节点留下的测试
    路由（路由表**全网共享**，任何面板改了都会推给对端）：关掉测试节点 + 清 42 个编译缓存目录 +
    核对用户 `config.json` 干净（routes 0 条、无测试设备名）。约定：跑测试节点必须**用临时配置目录
    + 非常用端口 + 跑完即关**。
  · v1.36 「正在发送的手机自动播放」其实就是蓝牙的「智连」 → 整块删掉那个全局勾（前端 id + 服务端
    配置项 `auto_play`），改由**每台设备卡片**的「智连」逐台决定，默认一台都不自动。
  · v1.37 测试残留路由**真删掉** → 路由表全网共享、两台机器互推（只删一边几秒就被推回来）：用两台
    机器自己的接口逐条删（本机 8 条、另一台 7 条），删完盯 60 秒无回流。并新增**"孤儿路由清扫"**
    （作者 + 两端都是本机从没见过的设备、过 3 分钟宽限自动清，记入"已删除"名单挡回流；
    离线只是 `online=False`、注册表里认识的设备一条都不动）。
  · v1.38 关系图"实线/虚线"和实际不符 → 原判据看"监控页里有没有出现这条路由的 id"，而
    "已配置 · 当前没有数据"的行**也带 `route_id`**（断开按钮要用它）→ 改成"这条流里**真的有数据**
    （字节或速率不为 0）才画实线"，图例同步改成一致口径。
  · v1.39 删掉「发现 已广播N次」那颗绿签（写的是内部广播次数，对用户没用）。
  · v1.39 "短小杂音" → 点对点接收端抖动缓冲原来对几毫秒的小缺口**一律补静音**（波形硬切到 0 再
    跳回来 = 一声"咔"）：缺口 ≤ 2ms 改成**保持最后一个采样**（直流保持，听不出来），更大的缺口才是
    真断流、仍补静音并记一次"下溢"；新增 `held_gaps` 计数与"下溢"分开算。孤儿路由清扫从每 0.5 秒
    **节流到每 30 秒**（它一旦真要清会触发会话重建 = 一声"咔"）。
  · v1.39 编译吃满 CPU 影响实时音频 → Nuitka 编译进程树整体降到**低于正常优先级**（音频优先，编译
    慢一点无所谓）；用户听音频时不主动跑会出声的自检。
  · v1.40 「智连按键反应不真实」（没开智连也自动开听） → 对端"自己自动过来听本机"这件事也要看本机
    卡片的「智连」：没开 → 引擎**拦下、不给声音**；开了 → 照常自动送；手动建的路由不受影响。
    卡片上直接出现红字"⛔ 想听本机但它没开智连 → 已拦下"，按钮变灰"智连没开·已拦下"。
  · v1.41 智连真拦住了（两个方向 + 兼容旧对端） → 三个根因全堵：① 本机原来**无条件**发一条
    "我在送你声音、请自动打开收听"的请求 → 改成只在「智连」开着时才发；② 旧版本推来的自动路由
    **没有 `auto` 标记**认不出 → 改成跨版本三种特征任一命中即算自动（`auto` 标记 / id 前缀
    `auto-listen-` / 标签文本）；③ 认出来之后还要**清掉**自动建的路由（听、送两个方向）并挡回流。
    顺带修真 bug：引擎里误用了只存在于**界面层**的函数名 `_name_of`（异常被 `except` 吞掉 →
    "智连开着也不生效、拦不住"）→ 改用注册表里的名字解析。
  · v1.42 修"串台" → 根因 `_attach_stream_routes` 的老兜底："发送方认不出身份 + 本机只有一个播放端
    就挂到那唯一一个端上"，把**认得出身份、但本机没给它开收听**的手机流挂到了别人那条路由上
    （监控页两个流共用同一个 `route_id`）→ 兜底**只给真认不出身份的发送方**；认得出的、本机没给它
    开收听的，一个播放端都不挂。
  · v1.43 监控页"点对点 / 广播"列原来写死一个字符串 → 按真实归属标：`route_id` 命中具名路由 =
    「点对点」，只落进频道（通配）那条 = 「广播」；关系图"本机在听广播"那片橙线的判据同步改。
  · v1.43 "手机对电脑的音质和速率很差"查证 → 一条知识：手机当时**还报 `v1.0.0`**（旧安装包没换），
    旧版本的采集/编码参数本就不同 → 先装新包再听。另记一条**接收缓冲自适应疑点**（目标缓冲被压到
    26ms，而迟到 / 溢出很大），**本轮没有动**流缓冲算法。
  · v1.44 监控页右上角新增「本机」开关 → 打开只显示本机收发的那几路、隐藏时钟通道；状态记在浏览器里；
    生效范围只在监控窗，控制台等页一点没动。
  · 手机端 v3.7 **停止本机声音采集时偷偷开了麦克风**（隐私问题） → `Engine.java` 的
    `onProjectionStopped()` / `onProjectionFailed()` 原来把采集端直接改成 `s.setSourceKind(SRC_MIC)`，
    而界面读的是另一个字段（还是"本机声音"）→ 一律落到"已停止 + 写明原因"，**绝不进麦克风**；
    两颗按钮改成真实状态 + 真开关（新增 `SourcePolicy`，每次刷新从引擎现读真实状态），
    开麦时"本机声音"如实显示为关（引擎同一时刻只采一路）。
