Audio Mixing v1.30 —— 版本说明（5 条界面修正 + 一个真性能故障）
2026-10-16

你这次 5 条都改了；另外在打包后跑测试时还抓到一个**真性能故障**（不是界面问题）。
 ① 这次换桌面 exe 时你正跑着 v1.29 —— 按你上次那句「停掉旧的，直接换」把旧实例停了再换（见最后一节）。
 ② 这一轮**没动手机端**，APK 还是 v3.2，手机上不用重装。

━━━ 先说那个真性能故障（很可能就是"越听越卡"的真凶）━━━

  打包 v1.29 之后跑 unittest，三条引擎测试突然红了，而且整套从 1.5 分钟变成 **8 分钟**。
  查根因：`apply_routes()` 每一轮（维护循环本就该 **0.5 秒**一轮）都要问一次"这台电脑配对了
  哪些蓝牙设备"，而那个枚举要起一个 PowerShell 子进程（**约 2.6 秒**）；缓存那一层原来要求
  "结果非空"才算命中缓存 —— 于是"现在一台配对的蓝牙设备都没有"的时候，**每一次都真去跑 2.6 秒**。
  实测 `tick()` 单次就是 **2.7 秒**，两个节点之间的音频流因此反复超时。

  → 用户侧的表现正好是"**越用越卡**"：音频路径被一个 2.6 秒的子进程反复拖住。
  修法：空结果同样算"刚查过"（把查询时刻记下来，空表也在有效期 20 秒内命中缓存）。
  修完实测：unittest 从 499 秒回到 **85 秒**，三条引擎测试全绿。

━━━ 图1：二维码看着像"优先级比同菜单其他项高"→ 改回去 ━━━

  两条根因：① 左栏那一个「监控」是链接、其余是按钮，样式本来就不一样；
  ② 更关键 —— 浏览器点完按钮会画一圈**焦点框**，它和"选中"长得太像：你那张图里
  「简洁」套着白圈、「二维码」是蓝底，看着像同一列有两项被选中。
  现在：左栏所有项样式统一（链接也按按钮样式画）、**去掉焦点框**，
  "选中"只由蓝色那一项表达，而且**永远恰好一项**。

━━━ 图2：「第一菜单有时候不能保持，直接第二菜单生效了」→ 双维度控制（像乘法）━━━

  上一版的错在于**把两个菜单塞进了同一个状态变量**：点标签会把二维码/版本号的选中冲掉，
  点二维码又看不出左边该亮哪一项 —— 于是"第一菜单保不住"。
  现在改成**两个互相独立、各自记住的两维**：
     · 页面维度：本机状态 / 设备与路由 / 广播 / 多耳机 / 二维码 / 版本号；
     · 密度维度：简洁 / 详细（对所有页都生效）。
  高亮规则：左栏**永远恰好一项** —— 在四个标签页时亮当前密度（简洁或详细），
  在二维码/版本号那两页时亮它自己；顶部那一行则永远亮"你上一次所在的标签页"。
  所以在二维码那页：左边亮「二维码」、上面亮「广播」，两个维度同时可见。
  （顺带：点「简洁 / 详细」时如果你正停在二维码/版本号，会回到上一次那个标签页 ——
   不然换了密度你也看不见，看着像"点了没反应"。）

━━━ 图3：局域网设备卡片要像蓝牙方块一样小 ━━━

  只"收紧"、不删任何东西：栅格 290→230px、卡片内边距与行距各收一档、
  名称字号 15.5→14px、电平方块 6px→5px、按钮也小一档。
  浏览器实测：局域网卡片 **240×120**，蓝牙方块 **160×80**。
  ★ 说清为什么做不到像素级一样：局域网卡片身上有**三根音量条 + 两个音量滑杆 + 三个按钮**
    （全是你点名要的），蓝牙方块只有一根条 + 三个按钮。要完全一样就得把两个滑杆收起来
    （例如点一下展开）——**你说一句我就改**，这次我不擅自删。

━━━ 图4：蓝牙区块下的「Wi-Fi 送声音的手机」还没删 ━━━

  整块删掉（标题 + 刷新 + 那个列表）。能力一个都没丢，如实说明：
     · 正在送声音的手机现在就在**上面那些设备卡片**里；
     · 「频道 → 音源」那个下拉仍然把它们列出来（标着「手机（正在送声音）」）；
     · 「手机在发、但没加进音源所以听不到」那句提醒还在（挪到频道那页的音源行下面了，
       那个「加入并开直通」按钮也还在）。
  ★ 那一段原来还带**每台手机的音量滑杆 + 一个静音按钮**，跟着一起删了：
    音量现在由设备卡片上的「我听它的」承担（走同一个 /api/mic/gain）；**静音不再单独提供**。
  ★ 下面那两个开关（正在发送的手机自动播放 / 自动接受收听请求）**留着** ——
    它们不是"手机 WiFi 的界面"，是行为开关，有服务端配置项和测试盯着。

━━━ 图5：内容不足时版本号不在框的左下角 ━━━

  根因：左栏没有被拉伸到窗口高度（`.app` 用的是 align-items:flex-start），
  于是"把版本号推到最下面"那条 CSS 根本不起作用 —— 内容少时它就浮在半空。
  现在左栏撑满窗口高度，版本号**贴左下角**；并按你要求**换成两行**：
  一行版本、一行「构建 2026-10-16」（**只到天**，不再带时分）。
  浏览器实测：`#verline` 底边离窗口底 17.6px（就是左栏自己的 18px 内边距）。

━━━ 怎么验的 ━━━

   · 电脑端 **285 项** unittest 全绿（新增：空蓝牙表要进缓存 2 项、双维度控制 1 项、
     版本号两行贴底 1 项、局域网卡片收紧 1 项）
   · 门禁全 PASS（check_ui_syntax / check_quality_curves / check_page_js / check_self_loop /
     check_multi_output / check_p2p_signal / check_android_proto / check_apk）、
     audit_leftovers **0 error**
   · **浏览器实测逐条验了这 5 条**（真起了面板、真点了每一页、量了数值）：
     左栏恰好一项高亮、两个维度互不影响、局域网卡片 240×120 / 蓝牙 160×80、
     netAudioList 为 null 且页面上没有那行字、`#verline` 两行且贴左下角、
     无横向溢出、内容块无重叠
   · 新 exe：verify_exe --quick **12/12**、selftest_twonode **19/19**、check_phone_stream PASS
   ★ 顺手修掉打包工具自己的一个隐患：它的自检原来写死 17800 —— 你正开着面板时，
     那个自检会打到**你那个旧实例**上（"面板已响应"其实是**假通过**），而且会挤掉你正在跑的实例。
     现在自检跑在一个临时空端口上，**再也碰不到你正在跑的那一个**。

━━━ 还没改的 / 改不了的（如实列）━━━

  1. **蓝牙音量测不到**：Windows 不提供蓝牙链路的丢包/重传计数，手机蓝牙进来的声音也不经过
     本工具 —— 蓝牙那一路只有「不可测」和链路状态词。这是事实，不是没做。
  2. **强杀退出挂不断蓝牙**：只有正常运行退出（托盘 / Ctrl+C）才挂断。
  3. **局域网卡片与蓝牙方块做不到像素级同高**（见图3，等你一句话）。
  4. 手机端的界面版式这一轮没动（图1~图5 都是电脑面板的）。
